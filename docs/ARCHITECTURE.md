# Architecture

## Текущее состояние

Репозиторий находится на историческом коммите `cf4281078464917ee7a39d2af1e5656a217223f6` в ветке `next`. Текущий продукт — Tauri 2 desktop shell с React 18 и TypeScript frontend. Локальные данные хранятся через SQLite Tauri plugin; состояние интерфейса хранится в Zustand и `localStorage`; ответы модели приходят через потоковый HTTP API.

Текущая реализация является исходным материалом, а не целевой архитектурой. В ней UI-компоненты напрямую используют базу данных, Tauri API и LLM-клиент. Крупные компоненты и инфраструктурные модули содержат несколько ответственности. Новая разработка не должна расширять эти связи.

## Текущие слои

```text
React components
  -> Zustand stores / local state
  -> db, lib/llm, lib/tauri, localStorage
  -> SQLite, Tauri commands, external API
```

Этот путь удобен для прототипа, но он привязывает интерфейс к инфраструктуре, усложняет тестирование и не позволяет безопасно сменить AI-провайдера.

## Реализованный срез Adaptive GenUI

Первый срез сохраняет текущую оболочку чата и правую панель Artifacts:

```text
Ответ модели
  → Glow UI fence parser + schema validation (src/lib/genUi.ts)
  → Artifact(kind=genui) в SQLite
  → общий безопасный React renderer в ChatPane или ArtifactsPanel
```

Поддерживаемые типы `glow-ui/v1`: таблица, числовой график, выбор варианта и ограниченный калькулятор. Калькулятор использует числовые поля и ползунки, а формула разбирается собственным арифметическим парсером с поддержкой только объявленных полей, чисел, скобок и `+ - * /`; вычисление не использует `eval` и не исполняет модельный код. Невалидная структура не исполняется; она остаётся обычным текстом ответа. Таблицы и графики отображаются через React/SVG, значения не интерпретируются как HTML или JavaScript. Обычный ответ остаётся текстовым по умолчанию.

Inline- и Workspace-представления используют одну запись Artifact и один `artifactId`. Раскрытие и возврат в чат не вызывают модель. Лёгкое состояние вида диаграммы и значений калькулятора хранится в `localStorage` по `artifactId`; содержимое и снимки предыдущих версий — в SQLite (`artifacts` и `artifact_revisions`). При явном запросе на изменение активного Artifact сохраняется предыдущая версия и обновляется запись с прежним ID. Studio, произвольные формы и дополнительные типы компонентов пока не реализованы.

HTML остаётся отдельным типом Artifact. Компактные интерактивные объяснения содержат явную метку `<meta name="glow-display" content="inline">` и отображаются внутри сообщения. Большие приложения и прежние HTML-артефакты по умолчанию остаются в Workspace; Design mode также сохраняет Workspace. Метка определяет только представление, не права исполнения.

Оба представления используют общий `HtmlArtifactFrame`: iframe с `sandbox="allow-scripts"` без `allow-same-origin` и CSP, запрещающей внешние ресурсы, сетевые запросы и отправку форм. Код не получает доступ к Tauri, API-ключам или действиям приложения. Мост `src/lib/htmlArtifact.ts` принимает только ограниченное JSON-состояние (до 16 КБ) от конкретного iframe с совпадающим каналом; команд и host-action в протоколе нет. Отдельное сообщение о высоте содержимого подстраивает inline-блок в пределах 240–640 px; большие мини-приложения остаются прокручиваемыми.

Новые встроенные схемы используют `glow-ui` с типом `diagram`, а не HTML: проверяемые поля, точки с формулами координат, отрезки и вычисляемые результаты. `InteractiveDiagram` рисует SVG в теме Glow и сохраняет пропорции при подгонке размера. Управление параметрами и результатом переиспользует нативный калькулятор. Общий parser поддерживает `+ - * / ^`, `pi`, `sin/cos/tan/sqrt/abs/log/exp`, `pow/min/max`; тригонометрия работает в радианах. `eval`, JavaScript и произвольные вызовы запрещены. Деление на ноль, тангенс в точке разрыва и нечисловой результат показываются как неопределённые. Автотесты: `node --test tests/genUi.test.mjs` (Node с поддержкой TypeScript type stripping).

Планы подготовки используют нативный тип `study_plan`: `days[].topics[].tasks[]`. Проверка структуры и чистые операции над отметками/прогрессом находятся в `src/lib/studyPlan.ts`, рендерер — `StudyPlan.tsx`. Модель не задаёт процент и начальные отметки: прогресс вычисляется по выполненным листовым задачам. `artifactViewState.studyCompleted` сохраняет только отмеченные задачи в существующем локальном хранилище. Ключ включает путь IDs и отпечаток содержания задачи, поэтому изменение задачи не наследует прежнее выполнение. Темы раскрываются нативными `details/summary`, прогресс доступен как `progressbar`. Автотесты: `node --test tests/genUi.test.mjs tests/studyPlan.test.mjs`. Состояние чата и локальных отметок имеют разный жизненный цикл; сохранение отметок не означает, что браузерная MemoryDb сохраняет сам чат после перезагрузки.

Прежние компактные HTML-канвасы с inline-маркером сохраняют совместимость: используют общую тему Glow и базовые стили элементов управления даже после переноса в Workspace. Тема передаётся из каталога приложения; её переключение обновляет CSS-переменные без пересоздания iframe и потери введённых значений. Обычные самостоятельные HTML-сайты в Workspace не получают эти переопределения. Произвольную графику, нарисованную JavaScript на bitmap canvas, CSS автоматически перекрасить не может.

Значения полей формы сохраняются автоматически. Для собственного состояния мини-приложение может использовать только `window.Glow.loadState()` и `window.Glow.saveState(jsonObject)`. Состояние хранится локально по `artifactId` и отпечатку HTML: перемещение между представлениями сохраняет его, изменение исходного HTML начинает новый набор состояния. Пароли, скрытые поля и файлы не считываются автоматическим мостом. Автоматически сохранять произвольные переменные JavaScript, состояние DOM или таймеры нельзя: их автор должен явно подключить JSON API. Загрузка сгенерированного HTML в несандбоксированную вкладку отключена.

## Целевая модель

```text
Presentation
  React feature UI and view models
      ↓
Application
  use cases: chat, conversation, project, artifact, file
      ↓
Domain
  stable entities, value objects and policies
      ↓
Ports
  LLM provider, persistence, identity, files, tools, telemetry
      ↓
Adapters
  Tauri, SQLite, backend gateway, cloud sync, provider SDKs
```

Зависимости направлены внутрь: domain не зависит от React, Tauri, SQLite или конкретного AI API. Application зависит от портов, а не от их реализаций. Presentation вызывает use cases и не выполняет SQL или сетевые запросы поставщика напрямую.

## Границы модулей

- **Chat**: жизненный цикл сообщения, streaming, отмена, ошибки и история.
- **Conversation**: дерево сообщений, заголовки и навигация по чатам.
- **Model access**: нейтральный контракт запросов и событий ответа; адаптер на каждого провайдера.
- **Persistence**: репозитории доменных сущностей; реализация SQLite является деталью.
- **Artifacts**: отдельная модель рабочих результатов, не парсер произвольного текста в UI.
- **Files**: явный импорт, метаданные, извлечение контекста и политика приватности.
- **Tools**: каталог возможностей, разрешения, аудит действий и изолированные адаптеры.
- **Identity and sync**: отдельный модуль, который не влияет на базовый локальный chat flow.

## Безопасность как архитектурное требование

API-ключи провайдеров не должны храниться в browser `localStorage` и не должны быть частью клиентского приложения. Production-маршрутизация моделей происходит через backend gateway. Доступ к файлам, shell-командам и инструментам предоставляется по принципу минимальных привилегий, с явным согласием пользователя и ограниченной областью действия.

## Правила развития

1. Новая функция получает собственную модульную границу до реализации.
2. Нельзя добавлять прямую инфраструктурную зависимость в UI ради скорости.
3. Изменение публичного доменного контракта документируется ADR.
4. Синхронизация и облако подключаются после устойчивого local-first сценария.
5. Модель, провайдер и transport считаются заменяемыми адаптерами.
