# Токеновые лимиты

## Решение

Проблема: лимит пользователя должен означать реальное количество токенов, а не
число запросов или условные денежные единицы.

Рассмотрены клиентская оценка текста, постфактум-списание и резерв с последующим
подтверждением usage. Выбран резерв: параллельные запросы не расходуют один остаток
дважды. Приоритет — честное отображение и серверная проверка.

После миграции 007 сервер списывает `usage.total_tokens`, проверяя равенство
`prompt_tokens + completion_tokens`. История, системные инструкции и вывод входят
в расход. Коэффициенты стоимости моделей не применяются. Клиент не определяет
списание. OpenRouter передаёт usage в последнем SSE-событии:
https://github.com/OpenRouterTeam/docs/blob/main/cookbook/administration/usage-accounting.mdx

Резерв — консервативная оценка UTF-8 размера истории с запасом на оболочку и
максимальный ответ. Это не точный токенизатор и не итоговый расход. Запрос может
быть отклонён, когда остаток меньше резерва, даже если фактический ответ оказался
бы коротким. Если провайдер подтверждает больший расход, записывается реальное
значение без урезания; доступный остаток становится нулём.

При подтверждённом отказе провайдера резерв освобождается без списания. При
прерывании/отсутствии usage резерв остаётся отдельно в статусе pending: нет
выдуманного списания и нет небезопасного возврата. Автоматическая сверка таких
запросов по generation ID пока не реализована; перед масштабированием обязательна.
Существующий общий дневной потолок запросов и ограничение частоты сохраняются.

## UI и права

Верхняя плашка удалена. Выход находится в настройках аккаунта; администрирование
показывается только при подтверждённой сервером роли admin. Все серверные операции
дополнительно проверяют права. Пользователь видит только свой баланс; администратор
видит метаданные расхода (модель, токены, статус, время), не содержание чужих чатов.

Процентная полоска показывает фактический расход относительно суммарных начислений;
резерв отображается отдельно. Автоматического обновления лимита по расписанию нет.
Журнал показывает последние 200 запросов и время с часовым поясом устройства.

## Переход

Старый журнал request credits сохраняется. Он не переводится автоматически:
7 запросов не равны 7 токенам. Новые wallets существующих пользователей стартуют
с нуля; администратор должен явно начислить токеновый лимит. Начальные лимиты новых
приглашений после миграции трактуются как токены. Миграция и приложение развёртываются
согласованно; до миграции новый сервер закрывает AI-запросы, не обходя квоты.

Статус на 13 октября 2026: миграция 007 применена; tests/tokenDatabase.sql прошёл
с полным откатом. 39 модульных тестов и production-сборка проходят. Проверка
published E2E после публикации ещё требуется.
