# Glow: отложенные возможности и условия возврата

Обновлено 13 октября 2026. Локальная реализация; публикация не выполнялась.

## Сохранённый задел

Полная копия прежнего экрана настроек: `docs/archive/SettingsModal.pre-v1.tsx.txt`.
Существующие компоненты DevicesSection, ExtensionsPanel, AgentsPanel, StudyPanel,
AppsAndExtensions и SettingsPanel остаются в исходниках, но не доступны через интерфейс первой версии.
Сохранённые значения старых настроек не удаляются. Автоматическая гидратация
экспериментальных расширений и их подсказки модели отключены.

| Возможность | Почему скрыта | Когда вернуть |
|---|---|---|
| Reflect | Пустой экран | Реальный анализ истории и памяти с проверяемым результатом |
| Time and focus: Break reminders, Quiet hours | Нет работающих напоминаний/ограничений | Фоновое расписание, сохранение, уведомления и тест закрытой вкладки |

| Полный Jupyter | Парсинг ячеек и изолированное выполнение Python уже реализованы | Персистентные kernels, пакеты, работа с ресурсами; не открывать notebook-панель автоматически при вложении |

Обычные вложения: фото, PDF, DOCX/XLSX/PPTX, текст и IPYNB.
Специализированные DICOM/3D просмотрщики сохранены в коде; широкую витрину
расширений не возвращаем. Подробности: `docs/ATTACHMENTS_QA_2026-10-13.md`.

## Что подключено в первой версии

- Web search: по умолчанию автоматически включается для свежих событий, новостей,
  медицинских запросов, научных публикаций, цен/курсов и явного запроса поиска.
  Обычные объяснения и локальные задачи с кодом остаются без поиска; ручной
  переключатель по-прежнему включает поиск всегда. Сервер задаёт только
  `openrouter:web_search`: Exa, до пяти поисков, до шести результатов за поиск,
  до 30 суммарно, до 6000 символов; `openrouter:web_fetch` до пяти открытий страниц.
  Произвольные инструменты от клиента не передаются провайдеру. Полученные
  аннотации отображаются под ответом как компактные ссылки с фавиконками; во время
  ответа показывается индикатор проверки сайтов. Ключи и лимиты остаются серверными.
  Требуется повторный живой тест на OpenRouter после восстановления сети.
  Локальный поиск идёт через отдельный Vite proxy в OpenRouter с серверным ключом.
  Реальный локальный запрос GLM 5.3 Flash с поиском выполнился: ответ содержит
  ссылки на документацию Anthropic и источник из аннотации провайдера.
  Проверка опубликованного endpoint после развёртывания остаётся; публикация не выполнена.
- Skills: библиотека встроенных инструкций и импорт самостоятельного SKILL.md;
  выбранный `/skill name` применяется к текущему пользовательскому запросу.
  Библиотека локальна и изолирована по аккаунту. Шаблон черновика не подменяет выполнение:
  инструкции навыка действительно попадают в контекст генерации.
- System theme сохраняет режим и реагирует на изменение системной темы.
- Reduced motion применяется в CSS и учитывает системную настройку.
- Память: переключатель управляет чтением и записью; факты можно просмотреть и удалить.
  По умолчанию выключена, старые факты не удаляются. Настройка локальна.
- Имя сохраняется в Supabase profiles для авторизованного пользователя.
- Уведомление о готовом ответе: отдельное разрешение пользователя, только
  успешный ответ при скрытой вкладке. Проверка системного уведомления ещё нужна.
- Privacy зависит от режима persistence. Экспорт/импорт явно описан как перенос
  локальных настроек, без чатов, файлов и сессии входа.

## Skills Claude: следующий этап

Формат SKILL.md совместим для самостоятельных инструкций; пакеты со scripts/,
references/, assets/ и требованиями инструментов пока отклоняются с пояснением.
Официальные docx/xlsx/pptx/pdf Skills Anthropic — отдельный этап, не завершённая функция.
Нужны Claude Messages API с code execution, серверный ключ, container.skills,
Files API, выдача файлов владельцу, продолжение pause_turn и полный учёт расходов.
Нельзя выдавать OpenRouter chat completions или браузерный Pyodide за эту среду.

Источники: https://platform.claude.com/docs/en/build-with-claude/skills-guide
и https://openrouter.ai/docs/guides/features/server-tools/web-search.

## Оставшиеся проверки

Два устройства одного аккаунта; два разных аккаунта; обычный пользователь и администратор;
сохранение имени после повторного входа; изменение системной темы; отказ поиска и ссылки;
лимиты с поисковым контекстом;
удаление памяти в local/cloud; реальная мобильная клавиатура.
Без этих проверок не считать облачную синхронизацию и установленный desktop полностью проверенными.

## Проверено в этой реализации

- Production build проходит (остаются предупреждения размера chunks).
- 49 модульных/серверных тестов проходят, включая поиск с резервированием/списанием
  и непропуск произвольных инструментов клиента, импорт и выбор Skills.
- Локальное меню + содержит Skills и Web search без Connectors/Plugins.
- Библиотека SKILL.md сохраняется после reload; импортированный навык реально
  отправлен модели, а не только вставлен в черновик. После исправления локального
  proxy модель ответила на запрос с `/skill qa-clear-writing`.
- Мобильные настройки проверены при 390×844: навигация прокручивается по горизонтали,
  содержимое — по вертикали; неготовых пунктов нет.
- Локальный proxy направляет ключ OpenRouter в OpenRouter, а не в старый шлюз.
- Проверки локального UI выполнялись на отдельном origin 127.0.0.1:1422 с
  отключённой авторизацией/облачными данными, без изменений опубликованного аккаунта.
